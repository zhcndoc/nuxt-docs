[WebMCP](https://webmachinelearning.github.io/webmcp/) 是一项提议中的浏览器 API，允许页面向浏览器中的 AI 代理提供工具。这样，代理便可添加商品到购物车或提交表单，而不必猜测应该点击哪个按钮。Nuxt 可以将模板中已绑定的操作转换为 WebMCP 工具。

::important
此功能为实验性功能，依赖的 API 仍在设计中。只有在[支持 WebMCP 的浏览器](#browser-support)中才会注册工具。
::

在 `nuxt.config` 中启用此功能：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    webmcp: true,
  },
})
```

## 模板工具

在函数的 JSDoc 注释中添加 `@tool` 标记，并将该函数绑定到元素的 `@click`、`@submit` 或组件事件。Nuxt 会注册一个以函数命名的工具，并使用 JSDoc 摘要作为工具描述：

```vue [app/pages/index.vue]
<script setup lang="ts">
const { data: products } = await useFetch('/api/products')
const cart = useCart()

/**
 * Add one of a product to the cart. Use when the user wants to buy something.
 * @tool
 */
function addToCart (sku: string) {
  cart.value.push(sku)
}
</script>

<template>
  <ul>
    <li
      v-for="product in products"
      :key="product.sku"
    >
      {{ product.name }}
      <button
        :disabled="!product.inStock"
        @click="addToCart(product.sku)"
      >
        Add
      </button>
    </li>
  </ul>
</template>
```

这会注册一个 `add_to_cart` 工具，并具有以下行为：

- 参数来自模板，因此代理无法传入页面上不存在的 SKU。
- 在 `v-for` 中，代理会根据 `:key` 选择一个项目作为 `target`；共享工具 `list_targets` 会列出屏幕上显示的项目及其文本。
- `:disabled` 决定该工具或其目标是否可以运行。
- 调用会执行绑定的表达式，并将其返回值作为工具结果。

编写工具描述时，应说明工具能为用户做什么以及何时使用；不要描述实现细节。

`@tool` 后的标记用于描述操作：

| 标记 | 含义 |
| --- | --- |
| `readonly` | 该工具仅读取，因此代理可以自由调用它。 |
| `consequential` | 该操作会产生难以撤销的影响，因此浏览器或代理可能会先征求用户确认。 |
| `confirm` | 必须由用户完成操作。调用会突出显示相应控件（或填入表单），并返回 `status: "requires_user_action"`，而不会执行操作。 |
| `values` | 对于表单，会将字段当前值作为默认值发送给代理。参阅[调用可以读取和更改什么](#what-a-call-can-read-and-change)。 |

```ts
/**
 * Place the order for everything in the cart. Use when the user is ready to pay.
 * @tool consequential
 */
function checkout () {}
```

## 表单

绑定到 `@submit` 的 `@tool` 函数会成为表单工具。表单的 `v-model` 绑定构成工具输入；调用会先将输入写入这些绑定，再提交表单，因此你自己的验证和提交处理程序会照常运行。读取表单中 `v-for` 或插槽变量的字段，其 `v-model` 不属于工具输入。

可通过 `@input` 传入[标准 Schema](https://standardschema.dev)（例如 Zod、Valibot 或 ArkType），或将其绑定到表单的 `:schema`，以验证输入。实现标准 JSON Schema 的架构也可用于描述代理输入，例如 Zod 架构，或通过 `@valibot/to-json-schema` 中的 `toStandardJsonSchema()` 包装的 Valibot 架构。否则，输入类型将根据当前值和原生控件推断，字段标签则作为描述。

```vue [app/pages/contact.vue]
<script setup lang="ts">
import { z } from 'zod'

const contactSchema = z.object({
  email: z.email(),
  message: z.string().min(5),
})
const form = reactive({ email: '', message: '' })

/**
 * Send a message to the shop. Use when the user has a question about an order.
 * @tool
 * @input contactSchema
 */
async function sendMessage () {
  await $fetch('/api/contact', { method: 'POST', body: form })
  return 'Sent.'
}
</script>

<template>
  <form @submit.prevent="sendMessage">
    <label>Email <input
      v-model="form.email"
      type="email"
    ></label>
    <label>Message <textarea v-model="form.message" /></label>
    <button type="submit">
      Send
    </button>
  </form>
</template>
```

写入任何值之前，系统都会先根据架构验证输入。写入后还会检查 `required` 或 `type="email"` 等原生约束；如果检查失败，表单会恢复原状。

### 调用可以读取和修改什么 {#what-a-call-can-read-and-change}

表单工具仅填充浏览器报告为已呈现且未禁用或只读的字段。为任何其他字段提供值的调用都会被拒绝。

只有当带有 `v-model` 的元素可见时，该字段才会被视为已渲染。以下字段不符合条件：被 `v-if` 移除的字段、`<input type="hidden">`，以及被隐藏的字段或位于隐藏元素中的字段。隐藏方式包括使用 `v-show`、`hidden` 属性、`display: none`、`visibility: hidden`、`opacity: 0`，或位于关闭的 `<details>` 中；无论隐藏设置来自模板还是样式表，均适用。通过可见 `<label>` 隐藏的复选框或单选按钮仍算作已渲染。

呈现的字段在以下情况下仍会被拒绝：

- 字段已禁用，例如具有 `disabled` 属性、位于已禁用的 `<fieldset>` 中，或具有 `aria-disabled="true"` 或 `data-disabled`。
- 字段为只读，例如具有 `readonly` 属性或 `aria-readonly="true"`。
- 字段位于具有 `inert` 属性的元素中。
- 组件在模板中将 `disabled` 或 `readonly` 属性设为 `true`。
- `<option>`、单选按钮或复选框已禁用。
- 字段值不在任何可用选项中；被 `hidden` 属性或 `display: none` 隐藏的 `<option>` 或 `<optgroup>` 不计入可用选项。

如果提交值与禁用或只读字段已发布的默认值相同，则仍会接受该值。

默认情况下，表单字段的当前值不会发送给代理。添加 `values` 标记后，这些值会作为默认值提供给代理，使其能够读取已填写的内容：

```ts
/**
 * Save the profile. Use when the user wants to change their details.
 * @tool values
 */
function saveProfile () {}
```

即使设置了 `values`，以下字段的当前值仍会被忽略：

- 字段未渲染。
- 字段具有 `type="password"`。
- 字段的 `autocomplete` 为 `current-password`、`new-password`、`one-time-code` 或银行卡信息（例如 `cc-number`）。
- 架构将该属性、包含该属性的对象或其内部属性标记为 `writeOnly`。

表单加载时会读取默认值，因此之后隐藏的字段仍会保留当时提供的默认值。

对于组件，系统会根据接收组件属性的元素判断其是否已渲染。其他属性则根据该元素及其中第一个原生控件判断。

::warning
未检测到某些限制：

- 移出屏幕、被其他元素裁剪或遮挡的字段仍会被视为已渲染。
- 如果组件隐藏了内部控件，但外围元素仍可见，该字段仍会被视为已渲染。
- 无论字段是否禁用，架构中声明的属性默认值都会按原样提供。不要在架构默认值中放置机密信息。
- 设置 `values` 后，若字段未带有上述任何标记，其机密值可能会作为默认值提供。请在架构中为该字段指定 `type="password"`、匹配的 `autocomplete` 或 `writeOnly` 属性。
- 通过其他方式禁用的组件（例如使用对象进行 `v-bind` 或在组件内部禁用）仍会被视为可编辑，除非其渲染出的元素具有上述属性之一。
- 如果组件属性没有反映到实际渲染的元素上，就无法填充该组件。

这些检查旨在让代理了解页面上实际提供给用户的内容。与处理其他请求一样，服务器仍必须验证并授权每次提交。
::

## 代码工具

对于未绑定到单个控件的工具，请使用 `defineAgentTool()` 定义工具，并在组件中调用 `useAgentTool()` 注册：

```vue [app/components/ProductSearch.vue]
<script setup lang="ts">
import { z } from 'zod'

const searchProducts = defineAgentTool({
  name: 'search_products',
  description: 'Find products by name. Use when the user asks what is for sale.',
  input: z.object({ query: z.string() }),
  annotations: { readOnlyHint: true },
  execute: ({ query }, { signal }) => $fetch('/api/products', { query: { q: query }, signal }),
})

useAgentTool(searchProducts)
</script>
```

`input` 会验证每次调用；如果架构实现了标准 JSON Schema，它也会描述工具参数。对于其他架构，请使用 `inputSchema` 描述参数。

传入 `targets`（包含 `key` 和 `label`），即可让代理从多个项目中选择；设置 `enabled` 则可暂时禁用工具，而无需注销。代理会通过名为 `target` 的参数指定所选项目，因此带有 `targets` 的工具不能再使用 `target` 作为输入属性名。

## 显示代理的作用

`useAgentActivity()` 会返回正在进行的工具调用。你可以据此向用户显示代理正在执行的操作，并允许用户停止调用。停止调用会中止传给 `execute` 的 `signal`，代理也会收到不应重试的结果。`@tool` 函数作为绑定到的事件处理程序运行，不会接收 `signal`：对于表单工具，停止操作会在提交前中止并恢复表单；对于已开始执行的处理程序，则会等待其完成。

```vue [app/components/AgentStatus.vue]
<script setup lang="ts">
const { current, stop } = useAgentActivity()
</script>

<template>
  <p v-if="current">
    {{ current.message }}
    <button @click="stop">
      Stop
    </button>
  </p>
</template>
```

## 导航

Nuxt 还会注册一个名为 `navigate` 的工具，用于列出应用页面，使代理能够访问其他页面上的操作。页面切换时，工具会随之更新。设置 `navigate: false` 可禁用该工具：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    webmcp: { navigate: false },
  },
})
```

## 开发

构建时，如果某个绑定无法转换为工具（例如，`@tool` 函数被包装，或 `v-for` 使用数组索引作为键）、工具描述不符合 [WebMCP 工具设计指南](https://github.com/GoogleChromeLabs/webmcp-tools)，或表单字段缺少标签，Nuxt 都会发出警告。开发期间，如果工具或结果超出代理可处理的范围，Nuxt 也会发出警告。

即使 `nuxt dev` 使用 Vite 构建器，浏览页面时提供的工具也会写入 `.nuxt/webmcp/schema.json`，因此每个浏览器都能看到这些工具。你可以使用 [`webmcp-evals`](https://github.com/GoogleChromeLabs/webmcp-tools/tree/main/webmcp-evals) 检查模型是否选中了正确的工具。设置 `schema` 可将文件写入其他位置，设为 `false` 则可禁用此功能：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    webmcp: { schema: 'webmcp.schema.json' },
  },
})
```

## 浏览器支持 {#browser-support}

WebMCP 目前在 Chrome 中处于早期预览阶段，且默认未启用。如果浏览器不支持 WebMCP，Nuxt 就不会注册任何工具，应用的行为也与未启用此功能时相同。

若要在本地试用工具，请在 Chrome 中打开 `chrome://flags/#enable-webmcp-testing`，或使用 `--enable-features=WebMCP` 启动 Chrome，然后通过 `localhost` 打开应用。WebMCP 需要安全上下文。你还需要一个能够调用 WebMCP 工具的代理，例如 Chrome 扩展[模型上下文工具检查器](https://chromewebstore.google.com/detail/model-context-tool-inspec/gbpdfapgefenggkahomfgkhfehlcenpd)。

若要向用户提供这些工具，请[为网站注册 WebMCP Origin Trial](https://developer.chrome.com/origintrials/#/register_trial/4163014905550602241)，并将令牌添加到页面：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  app: {
    head: {
      meta: [
        { 'http-equiv': 'origin-trial', 'content': 'YOUR_ORIGIN_TRIAL_TOKEN' },
      ],
    },
  },
})
```

令牌绑定到注册时使用的源，并且会过期。因此，其他源（例如暂存环境或预览部署）需要各自的令牌。
