## 探索 Nuxt 模块

在使用 Nuxt 开发生产级应用时，你可能会发现框架的核心功能不足以满足需求。可以通过配置选项和插件来扩展 Nuxt，但在多个项目间维护这些自定义配置可能会很繁琐、重复且耗时。另一方面，如果开箱即用地支持每个项目的需求，会使 Nuxt 变得非常复杂且难以使用。

这也是 Nuxt 提供模块系统的原因之一，它使得扩展核心变得可行。Nuxt 模块是异步函数，在使用 [`nuxt dev`](/docs/4.x/api/commands/dev) 启动开发模式或使用 [`nuxt build`](/docs/4.x/api/commands/build) 为生产构建项目时，会按顺序运行。它们可以覆盖模板、配置 webpack loader、添加 CSS 库，并执行许多其他有用的任务。

最重要的是，Nuxt 模块可以作为 npm 包分发。这使得它们可以在不同项目之间复用并与社区共享，有助于创建一个高质量插件的生态系统。

## Add Nuxt Modules

Once installed, you can add them to the `modules` property in your [`nuxt.config.ts`](/docs/4.x/directory-structure/nuxt-config) file. Module authors will often provide additional usage steps and instructions.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
    // 使用 package name（recommended usage）
    '@nuxtjs/example',

    // Load local module
    './modules/example',

    // Add module with inline options
    ['./modules/example', { token: '123' }],

    // Inline module definition
    async (inlineOptions, nuxt) => { },
  ],
})
```

::warning
Nuxt modules now only take effect at build time. The `buildModules` property used in Nuxt 2 has been deprecated; it is recommended to use `modules`.
::

## 禁用模块 :badge[v4.3]{color="info" size="xs" class="align-middle"}

你可以通过在 Nuxt 配置中将模块的配置键设置为 `false` 来禁用该模块。当你想要禁用从层中继承的模块时，这尤其有用。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // 禁用 `@nuxt/image` 模块
  image: false,
})
```
