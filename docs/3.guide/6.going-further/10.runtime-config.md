## 暴露

要向应用的其余部分公开配置和环境变量，需要在 [`nuxt.config`](/docs/directory-structure/nuxt-config) 文件中使用 [`runtimeConfig`](/docs/api/nuxt-config#runtimeconfig-1) 选项定义运行时配置。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    // 只有服务器端可用的私有密钥
    apiSecret: '123',
    // public 中的键也会暴露给客户端
    public: {
      apiBase: '/api',
    },
  },
})
```

当把 `apiBase` 添加到 `runtimeConfig.public` 时，Nuxt 会把它加入到每个页面的 payload 中。我们可以在服务端和浏览器端通用地访问 `apiBase`。

```ts
const runtimeConfig = useRuntimeConfig()

console.log(runtimeConfig.apiSecret)
console.log(runtimeConfig.public.apiBase)
```

::tip
公共运行时配置可以在 Vue 模板中通过 `$config.public` 访问。
::

### 应用密钥

以 `app` 为前缀的运行时配置键由 Nuxt 保留（目前包括 `runtimeConfig.app` 和 `runtimeConfig.appSecret`）。请勿将它们用于你自己的值。

Nuxt 提供了私有的 `runtimeConfig.appSecret`，作为应用的根密钥。模块和服务器功能会使用 [`deriveSecret`](/docs/guide/going-further/server-imports#deriving-secrets) 从中派生各自的密钥，并且 [会话辅助函数](/docs/guide/going-further/server-imports#sessions) 默认使用它进行密封。该值默认为空字符串，仅在服务器端可用，并且你可以通过 `NUXT_APP_SECRET` 设置它，而无需在 `nuxt.config` 中声明此键。

生成一个至少包含 32 个随机字节的密钥：

```bash [Terminal]
openssl rand -base64 32
```

::important
为每个环境使用不同的值，但要确保该值在同一环境中的各次部署和服务器实例之间保持稳定。更改该值会使依赖它的任何会话或签名失效。
::

Nitro 会解析环境变量覆盖值，因此，仅由数字组成或看起来像 JSON 的密钥会被解析为数字、布尔值或对象，而不是字符串。请将这类值用引号括起来（`NUXT_APP_SECRET='"12345..."'`），或改为在 `nuxt.config` 中设置 `runtimeConfig.appSecret`。

在开发环境中，如果未设置 `appSecret`，Nuxt 会生成一个随机密钥并将其存储在 `.nuxt/app-secret` 中，这样依赖它的功能无需任何设置即可运行。已配置的值始终会按原样使用。派生密钥首次使用生成的值时，Nuxt 会记录一条警告。构建时不会生成密钥：请在每个部署环境中设置 `NUXT_APP_SECRET`。

除非某个模块或服务器功能使用 `NUXT_APP_SECRET`，否则 Nuxt 不会要求设置它。

### 序列化

你的运行时配置会在传递给 Nitro 之前被序列化。这意味着任何不能被序列化然后反序列化的东西（例如函数、Set、Map 等）都不应当在你的 `nuxt.config` 中设置。

如果需要把不可序列化的对象或函数传入应用，建议将这段代码放在 Nuxt 或 Nitro 的插件或中间件中。

### 环境变量

提供配置最常见的方式是使用 [环境变量](https://medium.com/chingu/an-introduction-to-environment-variables-and-how-to-use-them-f602f66d15fa)。

::note
Nuxt CLI 内置了对在开发、构建和生成过程中读取 `.env` 文件的支持。但运行构建后的服务器时，**不会读取你的 `.env` 文件**。
:read-more{to="/docs/directory-structure/env"}
::

运行时配置值会在运行时**自动被匹配的环境变量替换**。

有两个关键要求：

1. 自定义运行时配置变量必须在你的 `nuxt.config` 中定义。这可以确保任意环境变量不会暴露给你的应用代码。

1. 只有特定命名的环境变量可以覆盖运行时配置属性。也就是说，必须是以 `NUXT_` 为前缀的全大写环境变量，并使用 `_` 来分隔键和大小写变化。

::warning
将 `runtimeConfig` 值的默认值设为*名称不同的环境变量*（例如将 `myVar` 设为 `process.env.OTHER_VARIABLE`）只会在构建时生效，运行时会失效。
建议使用与 `runtimeConfig` 对象结构匹配的环境变量。

在 `nuxt.config` 中设置的值（包括从 `process.env` 读取的值）都会写入服务器构建产物。任何能够读取项目文件的人（包括访问你向网络开放的开发服务器的客户端）都可以读取这些值。请将私有值留空，并通过 `NUXT_` 环境变量提供，如[下方示例](#example)所示。
::

::warning
环境变量值会通过 [`destr`](https://github.com/unjs/destr) 自动转换为对应的 JavaScript 类型。例如，`NUXT_MY_VAR=4848e0` 会变为数字 `4848`。若要保留字符串类型，环境变量的值本身必须包含双引号：在 `.env` 文件中写作 `NUXT_MY_VAR='"4848e0"'`；直接设置变量时（例如在 shell、Dockerfile 或托管平台控制台中），请确保引号属于变量值，而不是被 shell 去掉（例如 `NUXT_MY_VAR='"4848e0"' node .output/server/index.mjs`）。

通过 [schema](#validating-with-a-schema) 声明的值会转换为 schema 指定的类型，因此对于 `z.string()`，`NUXT_MY_VAR=4848e0` 仍会作为字符串处理。
::

使用 `future.compatibilityVersion: 5` 时，每个环境变量值都会转换为被覆盖值的类型，而不是通过 `destr` 强制转换：

| 默认值类型 | 环境变量 | 值 |
| --- | --- | --- |
| `string` | `NUXT_MY_VAR=4848e0` | `'4848e0'` |
| `number` | `NUXT_MY_VAR=8080` | `8080` |
| `boolean` | `NUXT_MY_VAR=false` | `false`（也可以是 `true`、`1`、`0`、`yes`、`no`、`on` 或 `off`）|
| array | `NUXT_MY_VAR='["value"]'` | `['value']` |
| 对象 | `NUXT_MY_VAR='{"key":"value"}'` | `{ key: 'value' }`，会与默认值合并。|

普通的 `null` 或 `undefined` 默认值会被替换为空字符串，因此会作为字符串设置。若要保留 `null` 默认值，同时将变量转换为其他类型，请使用类似 `z.number().nullable().default(null)` 的 schema。

对象的嵌套键也可以单独设置，例如使用 `NUXT_SESSION_MAX_AGE` 设置 `runtimeConfig.session.maxAge`。对于不允许为空字符串的键，空环境变量会被忽略。

如果环境变量无法转换为 `nuxt.config` 中 schema 指定的类型，或在 `compatibilityVersion: 5` 下无法转换为任意 schema 或默认值的类型（例如数字类型的 `port` 收到 `NUXT_PORT=abc`），服务器将无法启动。对于由模块设置的 schema，Nuxt 会发出警告，并保留该值的默认值。请参阅[使用 schema 校验](#validating-with-a-schema)，了解如何在不提供默认值的情况下声明值的类型。

观看 Alexander Lichter 的视频，了解开发者在使用 runtimeConfig 时最常犯的错误。
::

#### 示例 {#example}

```ini [.env]
NUXT_API_SECRET=api_secret_token
NUXT_PUBLIC_API_BASE=https://nuxtjs.org
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: '', // 可以被 NUXT_API_SECRET 环境变量覆盖
    public: {
      apiBase: '', // 可以被 NUXT_PUBLIC_API_BASE 环境变量覆盖
    },
  },
})
```

### 使用 Schema 校验 {#validating-with-a-schema}

`runtimeConfig` 中的任意值都可以使用同时实现 [Standard JSON Schema](https://standardschema.dev/json-schema) 的 [Standard Schema](https://standardschema.dev)，例如来自 [Zod](https://zod.dev) 或 [ArkType](https://arktype.io) 的 schema，或使用 `toStandardJsonSchema()` 包装的 [Valibot](https://valibot.dev) schema。schema 会指定值的类型；如果 schema 有默认值，则该值会作为默认值使用。

```ts [nuxt.config.ts]
import { z } from 'zod'

export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: z.string(),
    session: z.object({
      maxAge: z.number().int().default(60 * 60),
      secure: z.boolean().default(true),
    }),
    public: {
      mode: z.enum(['preview', 'production']).default('production'),
    },
  },
})
```

没有默认值的值（例如上例中的 `apiSecret`）是必填项。构建时如果缺少该值，Nuxt 会发出警告；在提供该值之前（此处通过 `NUXT_API_SECRET` 提供），服务器不会启动。预渲染期间，只有读取缺失值时才会抛出错误，因此依赖该值的页面预渲染会失败，其他页面不受影响。使用 `z.string().optional()` 或 schema 库中的等效写法，可将值设为可选。

schema 也可以用于整个 `runtimeConfig`，可以在[图层](/docs/getting-started/layers)的 `nuxt.config` 中设置，也可以由模块通过 [`updateRuntimeConfig()`](/docs/api/kit/runtime-config#schemas) 设置。上层图层或你自己的 `nuxt.config` 中设置的普通值，会成为下层声明的 schema 的默认值。

除非启用了 `compatibilityVersion: 5`，否则只有在 schema 声明于 `nuxt.config` 中时，无效或缺失的值才会导致服务器或对应的预渲染页面失败。对于由模块设置的 schema，Nuxt 会在服务器启动时发出警告，并保留该值的默认值。

服务器启动时，Nuxt 会根据每个 schema 的精简描述检查运行时配置，包括每个值的类型、必填项以及枚举和联合类型的允许值。在开发和构建期间，Nuxt 还会针对与当前环境变量不匹配的值发出警告。

::note
schema 本身不会包含在服务器 bundle 中。最小长度或 URL 格式等细化校验不会执行，也不支持转换操作。
::

## Reading

### Vue 应用

在 Nuxt 应用的 Vue 部分，你需要调用 [`useRuntimeConfig()`](/docs/api/composables/use-runtime-config) 来访问运行时配置。

::important
客户端和服务端的行为不同：

- 在客户端，只有 `runtimeConfig.public` 和 `runtimeConfig.app`（Nuxt 内部使用）中的键可用，并且对象是可写且响应式的。

- 在服务端，整个运行时配置均可用，但它是只读的，以避免上下文共享。使用 [Nitro v3](/docs/getting-started/upgrade#testing-nitro-v3) 构建服务器时，所有请求共享同一个对象，因此在渲染一个请求时所做的更改会影响后续请求。在开发环境中，如果在服务端渲染期间修改了该对象，Nuxt 会记录警告。
::

```vue [app/pages/index.vue]
<script setup lang="ts">
const config = useRuntimeConfig()

console.log('运行时配置:', config)
if (import.meta.server) {
  console.log('API 密钥:', config.apiSecret)
}
</script>

<template>
  <div>
    <div>查看开发者控制台！</div>
  </div>
</template>
```

::caution
**安全提示：** 注意不要通过渲染或传递给 `useState` 的方式将运行时配置的键暴露给客户端。
::

### 插件

如果你想在任何（自定义）插件中使用运行时配置，可以在 `defineNuxtPlugin` 函数中使用 [`useRuntimeConfig()`](/docs/api/composables/use-runtime-config)。

```ts [app/plugins/config.ts]
export default defineNuxtPlugin((nuxtApp) => {
  const config = useRuntimeConfig()

  console.log('API 基础 URL:', config.public.apiBase)
})
```

### 服务器路由

你也可以在服务器路由中使用 `useRuntimeConfig` 来访问运行时配置。

```ts [server/api/test.ts]
export default defineEventHandler(async (event) => {
  const { apiSecret } = useRuntimeConfig(event)
  const result = await $fetch('https://my.api.com/test', {
    headers: {
      Authorization: `Bearer ${apiSecret}`,
    },
  })
  return result
})
```

::note
将 `event` 作为参数传递给 `useRuntimeConfig` 是可选的，但建议传入它，以便服务器路由在运行时通过[环境变量](/docs/guide/going-further/runtime-config#environment-variables)覆盖运行时配置。
::

Nuxt 会尝试使用 [unjs/untyped](https://github.com/unjs/untyped) 从提供的运行时配置自动生成 TypeScript 接口。

Nuxt 会根据运行时配置中每个值的类型或 schema 生成类型。服务器启动时，通过 schema 声明的值会转换为对应类型，因此生成的类型与应用实际收到的值一致。

如果某个值的类型无法由其默认值体现（例如没有默认值、枚举或联合类型），请[通过 schema 声明](#validating-with-a-schema)，而不是扩展 `RuntimeConfig` 接口：

```ts [nuxt.config.ts]
import { z } from 'zod'

export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: z.string(),
    public: {
      apiBase: z.url().default('/api'),
    },
  },
})
```

::warning
扩展 `nuxt/schema` 中的 `RuntimeConfig` 或 `PublicRuntimeConfig` 只会改变类型。没有 schema 的值仍会通过 `destr` 转换，因此扩展后的类型可能与应用实际收到的值不符。
::
