## 暴露

要向应用的其余部分公开配置和环境变量，需要在 [`nuxt.config`](/docs/directory-structure/nuxt-config) 文件中使用 [`runtimeConfig`](/docs/api/nuxt-config#runtimeconfig-1) 选项定义运行时配置。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    // 仅服务器端可用的私有密钥
    apiSecret: '123',
    // public 中的键也会暴露给客户端
    public: {
      apiBase: '/api',
    },
  },
})
```

当把 `apiBase` 添加到 `runtimeConfig.public` 时，Nuxt 会把它加入到每个页面的 payload 中。我们可以在服务端和浏览器端通用地访问 `apiBase`。

```ts
const runtimeConfig = useRuntimeConfig()

console.log(runtimeConfig.apiSecret)
console.log(runtimeConfig.public.apiBase)
```

::tip
公共运行时配置可以在 Vue 模板中通过 `$config.public` 访问。
::

### 应用密钥

以 `app` 为前缀的运行时配置键为 Nuxt 保留（目前是 `runtimeConfig.app` 和 `runtimeConfig.appSecret`）。请勿将它们用于你自己的值。

Nuxt 提供了一个私有的 `runtimeConfig.appSecret`，作为应用的根密钥。模块和服务器功能通过 [`deriveSecret`](/docs/guide/going-further/server-imports#deriving-secrets) 从中派生各自的密钥，[会话辅助函数](/docs/guide/going-further/server-imports#sessions) 默认也会使用它进行封存。该值默认为空字符串，且仅在服务器端可用；你可以通过 `NUXT_APP_SECRET` 设置它，而无需在 `nuxt.config` 中声明此键。

生成一个至少包含 32 个随机字节的密钥：

```bash [Terminal]
openssl rand -base64 32
```

::important
每个环境都应使用不同的值，但在该环境内的不同部署和服务器实例之间应保持稳定。更改此值会使依赖它的任何会话或签名失效。
::

在开发环境中，如果 `appSecret` 未设置，Nuxt 会生成一个随机密钥并将其存储在 `.nuxt/app-secret` 中，以便依赖该密钥的功能无需任何设置即可运行。已配置的值始终会按原样使用。派生密钥首次使用生成的值时，Nuxt 会记录一条警告。构建时不会生成密钥：请在每个部署环境中设置 `NUXT_APP_SECRET`。

除非某个模块或服务器功能使用 `NUXT_APP_SECRET`，否则 Nuxt 不要求设置它。

### 序列化

你的运行时配置会在传递给 Nitro 之前被序列化。这意味着任何不能被序列化然后反序列化的东西（例如函数、Set、Map 等）都不应当在你的 `nuxt.config` 中设置。

如果需要把不可序列化的对象或函数传入应用，建议将这段代码放在 Nuxt 或 Nitro 的插件或中间件中。

### 环境变量

提供配置最常见的方式是使用 [环境变量](https://medium.com/chingu/an-introduction-to-environment-variables-and-how-to-use-them-f602f66d15fa)。

::note
Nuxt CLI 内置了对 `.env` 文件的支持，可在开发、构建和生成时读取该文件。但运行构建后的服务器时，**不会读取你的 `.env` 文件**。
:read-more{to="/docs/directory-structure/env"}
::

运行时配置值会在运行时**自动被匹配的环境变量替换**。

有两个关键要求：

1. 自定义运行时配置变量必须在 `nuxt.config` 中定义。这样可确保任意环境变量都不会暴露给应用代码。

1. 只有特定命名的环境变量可以覆盖运行时配置属性。也就是说，必须是以 `NUXT_` 为前缀的全大写环境变量，并使用 `_` 来分隔键和大小写变化。

::warning
将 `runtimeConfig` 值的默认值设置为“不同名称的环境变量”（例如将 `myVar` 设置为 `process.env.OTHER_VARIABLE`）仅在构建时有效，并在运行时中断。
建议使用与 `runtimeConfig` 对象结构匹配的环境变量。

`nuxt.config` 中设置的值（包括从 `process.env` 读取的值）将写入服务器构建输出。任何可以读取您的项目文件的人（包括您暴露在网络上的开发服务器的客户端）都可以读取它们。将 `nuxt.config` 中的私有值保留为空，并为它们提供 `NUXT_` 环境变量，如下面的示例 ](#example) 所示。
::

环境变量值将转换为它们替换的值的类型：

|默认类型 |环境变量 |价值|
| --- | --- | --- |
| `string` | `NUXT_MY_VAR=4848e0` | `'4848e0'` |
| `number` | `NUXT_MY_VAR=8080` | `8080` |
| `boolean` | `NUXT_MY_VAR=false` | `false` （还 `true`, `1`, `0`, `yes`, `no`, `on` 和 `off`) |
| 大批 | `NUXT_MY_VAR='["value"]'` | `['value']` |
| 目的 | `NUXT_MY_VAR='{"key":"value"}'` | `{ key: 'value' }`，合并到默认值上 |

普通默认值 `null` 或 `undefined` 被替换为空字符串，因此它被设置为字符串。要保持 `null` 默认值并仍将变量强制为另一种类型，请使用 `z.number().nullable().default(null)` 等架构。

对象的嵌套键也可以单独设置，例如 `NUXT_SESSION_MAX_AGE` 为 `runtimeConfig.session.maxAge`。对于不能是空字符串的键，空变量将被忽略。

如果无法转换环境变量（例如 `NUXT_PORT=abc` 表示数字 `port`），则服务器不会启动。请参阅[使用 Schema](#validating-with-a-schema) 进行验证来声明值的类型而不为其提供默认值。

观看 Alexander Lichter 的视频，了解开发者在使用 runtimeConfig 时最常犯的错误。
::

#### 示例

```ini [.env]
NUXT_API_SECRET=api_secret_token
NUXT_PUBLIC_API_BASE=https://nuxtjs.org
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: '', // 可被 NUXT_API_SECRET 环境变量覆盖
    public: {
      apiBase: '', // 可被 NUXT_PUBLIC_API_BASE 环境变量覆盖
    },
  },
})
```

### 使用架构进行验证 {#validating-with-a-schema}

`runtimeConfig` 中的任何值都可以是 [标准架构](https://standardschema.dev)，它也实现了 [标准 JSON 架构](https://standardschema.dev/json-schema)，例如来自 [佐德](https://zod.dev) 或 [方舟型](https://arktype.io)] 的架构，或包装在 [瓦利博特](https://valibot.dev) 中的架构] `toStandardJsonSchema()`。架构设置值的类型，并使用其默认值（如果有）作为默认值。

```ts [nuxt.config.ts]
import { z } from 'zod'

export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: z.string(),
    session: z.object({
      maxAge: z.number().int().default(60 * 60),
      secure: z.boolean().default(true),
    }),
    public: {
      mode: z.enum(['preview', 'production']).default('production'),
    },
  },
})
```

需要一个没有默认值的值，例如上面的 `apiSecret`。 Nuxt 在构建时警告缺少值，并且在提供该值之前服务器不会启动（此处为 `NUXT_API_SECRET`）。预渲染时，仅读取缺失值会抛出异常，因此依赖于它的页面无法预渲染，而其他页面不受影响。使用 `z.string().optional()` 或架构库中的等效项将值设置为可选。

该模式还可以用于整个 `runtimeConfig`，在 [层](/docs/getting-started/layers) 的 `nuxt.config` 中设置，或由具有 [`updateRuntimeConfig()`](/docs/api/kit/runtime-config#schemas).在较高层或您自己的 `nuxt.config` 中设置的纯值将成为进一步声明的模式的默认值。

当服务器启动时，Nuxt 会根据每个模式的紧凑描述检查运行时配置：每个值的类型、需要哪些值以及允许的枚举和联合值。在开发和构建过程中，Nuxt 还会警告与当时使用的环境变量不匹配的值。

::note
架构本身不包含在您的服务器包中。不检查最小长度或 URL 格式等细化，也不支持转换。
::

## Reading

### Vue 应用

在 Nuxt 应用的 Vue 部分，需要调用 [`useRuntimeConfig()`](/docs/api/composables/use-runtime-config) 来访问运行时配置。

::important
客户端和服务端的行为不同：

- 在客户端，只有 `runtimeConfig.public` 和 `runtimeConfig.app`（Nuxt 内部使用）中的键可用，并且对象是可写且响应式的。

- 在服务器端，整个运行时配置可用，但您应该将其视为只读。它是每个请求共享的单个对象，因此渲染一个请求时所做的更改对于所有后续请求都是可见的。在开发过程中，Nuxt 在服务器端渲染期间发生变异时会记录警告。
::

```vue [app/pages/index.vue]
<script setup lang="ts">
const config = useRuntimeConfig()

console.log('运行时配置:', config)
if (import.meta.server) {
  console.log('API 密钥:', config.apiSecret)
}
</script>

<template>
  <div>
    <div>查看开发者控制台！</div>
  </div>
</template>
```

::caution
**安全提示：** 注意不要通过渲染或传递给 `useState` 的方式将运行时配置的键暴露给客户端。
::

### 插件

如果想在任何（自定义）插件中使用运行时配置，可以在 `defineNuxtPlugin` 函数中使用 [`useRuntimeConfig()`](/docs/api/composables/use-runtime-config)。

```ts [app/plugins/config.ts]
export default defineNuxtPlugin((nuxtApp) => {
  const config = useRuntimeConfig()

  console.log('API 基础 URL:', config.public.apiBase)
})
```

### 服务器路由

你也可以在服务器路由中使用 `useRuntimeConfig` 来访问运行时配置。

```ts [server/api/test.ts]
export default defineEventHandler(async (event) => {
  const { apiSecret } = useRuntimeConfig()
  const result = await $fetch('https://my.api.com/test', {
    headers: {
      Authorization: `Bearer ${apiSecret}`,
    },
  })
  return result
})
```

## 运行时配置类型

Nuxt 根据每个值的类型或其架构生成运行时配置的类型。服务器启动时，环境变量会转换为相同的类型，因此生成的类型描述您的应用程序收到的值。

要为值指定其默认值未描述的类型，例如没有默认值、枚举或联合的值，请使用 schema](#validating-with-a-schema) 声明它，而不是通过扩展 `RuntimeConfig` 接口：

```ts [nuxt.config.ts]
import { z } from 'zod'

export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: z.string(),
    public: {
      apiBase: z.url().default('/api'),
    },
  },
})
```

::warning
从 `nuxt/schema` 增强 `RuntimeConfig` 或 `PublicRuntimeConfig` 仅更改类型。值仍根据其默认值进行转换，因此增强类型可以描述您的应用程序从未收到的值。
::
