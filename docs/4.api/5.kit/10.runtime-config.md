## `useRuntimeConfig`

在构建时，可以访问已解析的 Nuxt [运行时配置](/docs/guide/going-further/runtime-config)。

匹配的环境变量的应用和转换方式与运行时相同。 `runtimeConfig` 中声明的模式将替换为其默认值。

::tip
优先选择 `useRuntimeConfig()` 而不是在模块中读取 `nuxt.options.runtimeConfig`。 `nuxt.options.runtimeConfig` 仅保留默认值，未应用环境变量。
::

### Type

```ts
function useRuntimeConfig (): Record<string, unknown>
```

## `updateRuntimeConfig`

也可以更新运行时配置。该配置将与现有的运行时配置合并，如果 Nitro 已经初始化，它会触发一个 HMR 事件以重新加载 Nitro 运行时配置。

### Schemas

传递给 `updateRuntimeConfig` 的值可以是 [图式](/docs/guide/going-further/runtime-config#validating-with-a-schema)，它设置值的类型及其默认值：

```ts
import { defineNuxtModule, updateRuntimeConfig } from '@nuxt/kit'
import { z } from 'zod'

export default defineNuxtModule({
  setup () {
    updateRuntimeConfig({
      myModule: z.object({
        apiKey: z.string(),
        retries: z.number().default(3),
      }),
    })
  },
})
```

该模式立即被其默认值替换，因此后续模块从 ​​`nuxt.options.runtimeConfig` 读取纯值。用户在同一路径中设置的值（例如 `nuxt.config` 中的 `runtimeConfig.myModule.apiKey`）将被保留并成为架构的默认值。用户在同一路径声明的模式优先于模块的模式。

直接将架构分配给 `nuxt.options.runtimeConfig` 会引发错误。

::note
在不支持运行时配置模式的 Nuxt 版本上，模式将被其默认值替换并且不会被验证。没有默认值的必需值将变为空字符串，因此环境变量仍然可以覆盖它。
::

### Type

```ts
function updateRuntimeConfig (config: Record<string, unknown>): void | Promise<void>
```
