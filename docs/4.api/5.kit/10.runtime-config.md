## `useRuntimeConfig`

在构建时，可以访问已解析的 Nuxt [运行时配置](/docs/guide/going-further/runtime-config)。

匹配的环境变量会以与运行时相同的方式应用并转换。`runtimeConfig` 中声明的 schema 会被替换为其默认值。

::tip
在模块中，建议使用 `useRuntimeConfig()`，而不是读取 `nuxt.options.runtimeConfig`。`nuxt.options.runtimeConfig` 只包含默认值，尚未应用环境变量。
::

### Type

```ts
function useRuntimeConfig (): Record<string, unknown>
```

## `updateRuntimeConfig`

也可以更新运行时配置。该配置将与现有的运行时配置合并，如果 Nitro 已经初始化，它会触发一个 HMR 事件以重新加载 Nitro 运行时配置。

### Schema

传递给 `updateRuntimeConfig` 的值可以是 [schema](/docs/guide/going-further/runtime-config#validating-with-a-schema)，用于指定值的类型和默认值：

```ts
import { defineNuxtModule, updateRuntimeConfig } from '@nuxt/kit'
import { z } from 'zod'

export default defineNuxtModule({
  setup () {
    updateRuntimeConfig({
      myModule: z.object({
        apiKey: z.string(),
        retries: z.number().default(3),
      }),
    })
  },
})
```

schema 会立即被替换为其默认值，因此后续模块从 `nuxt.options.runtimeConfig` 读取到的是普通值。用户在相同路径设置的值（例如 `nuxt.config` 中的 `runtimeConfig.myModule.apiKey`）会保留，并成为 schema 的默认值。若用户在相同路径声明了 schema，则用户的 schema 优先于模块的 schema。

除非用户启用了 `compatibilityVersion: 5`，否则不符合模块 schema 的值或缺失的必填值只会在服务器启动时触发警告，并继续使用默认值。

直接将 schema 赋给 `nuxt.options.runtimeConfig` 会抛出错误。

::note
对于不支持运行时配置 schema 的 Nuxt 版本，schema 会被替换为默认值，但不会进行校验。没有默认值的必填项会变为空字符串，因此仍可通过环境变量覆盖。
::

### Type

```ts
function updateRuntimeConfig (config: Record<string, unknown>): void | Promise<void>
```
