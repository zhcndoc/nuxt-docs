::tip
`<NuxtErrorBoundary>` 在底层使用了 Vue 的 [`onErrorCaptured`](https://vue.zhcndoc.com/api/composition-api-lifecycle#onerrorcaptured) 钩子。
::

默认插槽中的内容抛出错误时，会改为渲染 `#error` 插槽。启用 [`experimental.ssrErrorBoundary`](/docs/guide/going-further/experimental-features#ssrerrorboundary) 后，服务端渲染期间也会执行此行为：发生服务端错误时，HTML 响应（状态码为 `200`）中会包含 `#error` 插槽，并将错误传递给客户端，使水合后的状态保持一致。随后在客户端调用 `clearBoundaryError`，即可重新渲染默认插槽。

在生产环境中，非 HTTP 服务端错误（例如通过 [`createError`](/docs/api/utils/create-error) 创建的错误）会以通用 `500` 错误的形式传递给 `#error` 插槽，因此其消息和数据不会发送到浏览器。HTTP 错误会保留其 `status`、`message` 和 `data`。

::note
服务端错误捕获由 [`experimental.ssrErrorBoundary`](/docs/guide/going-further/experimental-features#ssrerrorboundary) 选项控制；将 `future.compatibilityVersion` 设为 `5` 时会启用该选项。关闭时，边界只会捕获客户端错误。
::

::warning
边界会捕获渲染默认插槽时抛出的所有错误，包括使用 `fatal: true` 创建的错误。它不会拦截绕过组件树的错误，例如调用 [`showError`](/docs/api/utils/show-error)、路由中间件抛出的错误，或 `useFetch`/`useAsyncData` 失败（这些失败会通过 `error` 返回，而不是抛出）。由 vapor 组件渲染的默认插槽只会在客户端捕获错误。
::

## Props

- `retryOnClient`：当错误在服务端渲染期间被捕获时，在客户端挂载后重新渲染默认插槽。适用于只会在服务端出错的内容（例如访问 `window` 的组件）：HTML 中会先提供 `#error` 插槽，随后在浏览器中替换为实际内容。如果默认插槽在客户端也抛出错误，则会再次渲染 `#error` 插槽并传入客户端错误。
  - **type**: `boolean`
  - **default**: `false`

  ```vue [app/pages/example.vue]
  <template>
    <NuxtErrorBoundary retry-on-client>
      <BrokeInSSR />
      <template #error>
        <p>Loading…</p>
      </template>
    </NuxtErrorBoundary>
  </template>
  ```

## 事件

- `@error`：当组件的默认插槽抛出错误时触发。若错误在服务端渲染期间捕获，则只会在服务端触发。

  ```vue [app/app.vue]
  <template>
    <NuxtErrorBoundary @error="logSomeError">
      <!-- ... -->
    </NuxtErrorBoundary>
  </template>
  ```

## 插槽

- `#error`：指定在发生错误时显示的回退内容。

  ```vue [app/app.vue]
  <template>
    <NuxtErrorBoundary>
      <!-- ... -->
      <template #error="{ error, clearBoundaryError }">
        <p>An error occurred: {{ error }}</p>

        <button @click="clearBoundaryError">
          Clear error
        </button>
      </template>
    </NuxtErrorBoundary>
  </template>
  ```

  ::warning
  插槽也会将 `clearError` 作为 `clearBoundaryError` 的已弃用别名提供。请使用 `clearBoundaryError`：如果模板未从插槽 props 中解构 `clearError`，则会调用自动导入的 [`clearError`](/docs/api/utils/clear-error)，清除的是**全局**错误。
  ::

## 示例

### 在脚本中访问 `error` 和 `clearBoundaryError`

你可以在组件脚本中访问 `error` 和 `clearBoundaryError` 属性，如下所示：

```vue [app/app.vue]
<template>
  <NuxtErrorBoundary ref="errorBoundary">
    <!-- ... -->
  </NuxtErrorBoundary>
</template>

<script setup lang="ts">
const errorBoundary = useTemplateRef('errorBoundary')

// errorBoundary.value?.error
// errorBoundary.value?.clearBoundaryError()
</script>
```
