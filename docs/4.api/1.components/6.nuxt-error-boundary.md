::tip
`<NuxtErrorBoundary>` 在内部使用了 Vue 的 [`onErrorCaptured`](https://vue.zhcndoc.com/api/composition-api-lifecycle#onerrorcaptured) 钩子。
::

当默认槽中的内容抛出异常时，`#error` 槽将在其位置呈现。这在服务器端渲染期间以及客户端上都有效：服务器端错误会导致 `#error` 插槽成为 HTML 响应的一部分（具有 `200` 状态），并且错误会传递到客户端，以便它合并为相同的状态。在客户端调用 `clearBoundaryError` 然后重新渲染默认槽。

在生产中，不是 HTTP 错误的服务器端错误（例如使用 [`createError`](/docs/api/utils/create-error) 创建的错误）作为通用 `500` 错误到达 `#error` 插槽，因此其消息和数据不会发送到浏览器。 HTTP 错误保留其 `status`、`message` 和 `data`。

::note
服务器端捕获由 [`experimental.ssrErrorBoundary`](/docs/guide/going-further/experimental-features#ssrerrorboundary) 选项控制，默认情况下启用。禁用时，边界仅捕获客户端错误。
::

::warning
边界捕获渲染默认槽时抛出的所有内容，包括使用 `fatal: true` 创建的错误。它不会拦截绕过组件树的错误，例如调用 [`showError`](/docs/api/utils/show-error)、路由中间件中抛出的错误或 `useFetch`/`useAsyncData` 失败（在 `error` 中返回而不是抛出）。由 Vapor 组件渲染的默认插槽仅在客户端上捕获。
::

## Props

- `retryOnClient`：当服务器端渲染期间捕获错误时，在安装后重新渲染客户端上的默认插槽。将此用于仅在服务器上失败的内容（例如，访问 `window` 的组件）：`#error` 插槽在 HTML 中提供，然后替换为浏览器中的真实内容。如果默认插槽也在客户端上抛出异常，则 `#error` 插槽将再次呈现，并出现客户端错误。
  - **类型**：`boolean`
  - **默认**：`false`

  ```vue [app/pages/example.vue]
  <template>
    <NuxtErrorBoundary retry-on-client>
      <BrokeInSSR />
      <template #error>
        <p>Loading…</p>
      </template>
    </NuxtErrorBoundary>
  </template>
  ```

## Events

- `@error`：当组件的默认槽抛出错误时发出事件。对于服务器端渲染期间捕获的错误，它仅在服务器上发出。

  ```vue [app/app.vue]
  <template>
    <NuxtErrorBoundary @error="logSomeError">
      <!-- ... -->
    </NuxtErrorBoundary>
  </template>
  ```

## 插槽

- `#error`：指定在发生错误时显示的回退内容。

  ```vue [app/app.vue]
  <template>
    <NuxtErrorBoundary>
      <!-- ... -->
      <template #error="{ error, clearBoundaryError }">
        <p>An error occurred: {{ error }}</p>
        <p v-if="error.status">
          {{ error.status }} {{ error.statusText }}
        </p>

        <button @click="clearBoundaryError">
          Clear error
        </button>
      </template>
    </NuxtErrorBoundary>
  </template>
  ```

`error` 属性是 `Error`，也可以携带 `status`、`statusText`、`data`、`cause` 和 `fatal`。服务器端错误始终是 `NuxtError`，因此这些字段存在，但当 Nuxt 不知道 `statusText`、`data` 和 `cause` 时，它们是 `undefined`。客户端上抛出的错误会在抛出时传递，因此这些字段仅在抛出的错误携带它们时才存在，例如使用 [`createError`](/docs/api/utils/create-error).

  ::warning
该插槽还将 `clearError` 公开为 `clearBoundaryError` 的已弃用别名。使用 `clearBoundaryError`：如果模板不从插槽属性解构 `clearError`，它将调用自动导入的 [`clearError`](/docs/api/utils/clear-error)，这会清除 **全局** 错误。
  ::

## 在脚本中访问 `error` 和 `clearError`

### 在脚本中访问 `error` 和 `clearBoundaryError`

您可以在组件脚本中访问 `error` 和 `clearBoundaryError` 属性，如下所示：

```vue [app/app.vue]
<template>
  <NuxtErrorBoundary ref="errorBoundary">
    <!-- ... -->
  </NuxtErrorBoundary>
</template>

<script setup lang="ts">
const errorBoundary = useTemplateRef('errorBoundary')

// errorBoundary.value?.error
// errorBoundary.value?.clearBoundaryError()
</script>
```
