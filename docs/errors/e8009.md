# E8009

使用流式传输路由时，页面抛出错误前，响应可能已经开始写入浏览器。此时 Nuxt 无法切换到新的错误响应，因此会以客户端可恢复的状态结束流：设置 `payload.error`，刷新 payload 脚本和剩余的 head 标签，并闭合文档，使浏览器在 hydration 期间渲染 `error.vue`。

如果该恢复过程本身失败，就会报告此诊断信息：例如无法渲染 shell 之后注册的 head 标签或闭合标签。此时浏览器收到的会是空白页或部分渲染的页面，而不是错误页面。

## 解决方法

请先修复原始页面错误。只有渲染过程中抛出错误时才会运行恢复逻辑，因此页面能够正常渲染后，此诊断信息就会消失。

如果底层错误是预期情况（例如上游请求可能失败），请在页面中处理错误，不要让错误传递到渲染器，以便在流提交之前发送正确的错误响应：

```vue [app/pages/blog.vue]
<script setup lang="ts">
const { data, error } = await useFetch('/api/content')

if (error.value) {
  throw createError({ statusCode: 404, statusMessage: 'Not found', fatal: true })
}
</script>
```

你也可以为路由禁用流式传输，使错误以普通错误响应的形式渲染，而不是在流传输过程中尝试恢复：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/blog/**': { streaming: false },
  },
})
```

如果页面错误已修复但仍然报告此问题，则说明失败发生在 head 渲染过程中。请检查 `useHead` 中是否有标签 getter 读取了应用处于错误状态时可能不存在的状态，并在报告问题时附上诊断信息中的原因。
