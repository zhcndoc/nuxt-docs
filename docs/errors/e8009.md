# E8009

路由以流式方式传输时，页面错误抛出时，响应已经开始写入浏览器。Nuxt 此时无法切换到全新的错误响应，因此会以客户端可恢复的状态完成数据流：设置 `payload.error`，刷新 payload 脚本和剩余的 head 标签，并关闭文档，以便浏览器在水合期间渲染 `error.vue`。

当此恢复过程本身失败时，就会报告此诊断：在 shell 之后注册的 head 标签或结束标签无法渲染。此时，浏览器收到的将是空白页面或部分渲染的页面，而不是你的错误页面。

## 解决方法

首先修复原始页面错误。此恢复路径只会在渲染抛出错误时运行，因此页面渲染成功后，此诊断就会消失。

如果底层错误是预期内的（例如可能失败的上游请求），请在页面中处理该错误，而不要让它传递给渲染器，这样就能在数据流提交前发送正确的错误响应：

```vue [app/pages/blog.vue]
<script setup lang="ts">
const { data, error } = await useFetch('/api/content')

if (error.value) {
  throw createError({ statusCode: 404, statusMessage: 'Not found', fatal: true })
}
</script>
```

你也可以让路由退出流式传输，这样错误就会作为常规错误响应渲染，而不是在数据流中途进行恢复：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/blog/**': { streaming: false },
  },
})
```

如果页面错误已修复，但仍报告此问题，则故障发生在 head 渲染本身。检查 `useHead` 中读取状态的标签 getter，确认它读取的状态在应用处于错误状态时可能存在，并请附上诊断中显示的原因进行报告。
